3. Arquitectura y Observaciones Técnicas Críticas (con Código)

🚨 Antimpatrón: Servicios API Acoplados en Mixins Vue

El Problema: Las llamadas Axios están encapsuladas usando Vue Mixins (ej. src/mixins/services/loginMixin.js). Esto genera colisión de nombres de métodos en los componentes, dificulta el testing unitario y rompe la separación de responsabilidades (SoC), ya que el componente de Vista se entrelaza lógicamente con la capa de Red/Repositorio.

Código Actual:

// src/mixins/services/loginMixin.js
import axios from "axios";
import { basePath } from '@/config';

const notificationsMixin = {
    methods: {
        getLoginToEmailPassword(filter) {
            return axios.post(`${basePath}/api/users/session`, filter, config)
                .then(response => response.data)
                .catch(error => {
                    this.$toast.error('Problemas para obtener el usuario');
                })
        }
    }
}
export default notificationsMixin;

Refactorización Propuesta (Patrón Repositorio):

// 1. Crear instancia base: src/api/httpClient.js
import axios from "axios";
import { basePath } from '@/config';

const httpClient = axios.create({
    baseURL: basePath,
    headers: { 'Content-Type': 'application/json;charset=UTF-8' }
});

// Interceptor para inyectar token siempre actualizado
httpClient.interceptors.request.use(config => {
    const token = localStorage.getItem('token');
    if (token) config.headers.authorization = `Bearer ${token}`;
    return config;
});
export default httpClient;

// 2. Extraer el servicio: src/api/services/authService.js
import httpClient from '../httpClient';

export const AuthService = {
    login(credentials) {
        return httpClient.post('/api/users/session', credentials);
    },
    getUser(userId) {
        return httpClient.get(`/api/users/${userId}`);
    }
};

// 3. Uso en el Componente Vue (Limpiamente importado):
import { AuthService } from '@/api/services/authService';

export default {
    methods: {
        async handleLogin() {
            try {
                const { data } = await AuthService.login(this.form);
            } catch (err) {
                this.$toast.error('Error en login');
            }
        }
    }
}

⚠️ Manejo de Token y Dependencia Fuerte de LocalStorage

El Problema: La variable config en el mixin principal (loginMixin.js) se evalúa una sola vez cuando el archivo es importado (en la fase de parseo del módulo). Si el usuario hace login, el token muta en localStorage, pero config.headers.authorization retendrá el valor viejo (posiblemente nulo). Esto obliga a recargas forzadas del navegador (window.location.reload) que rompen la esencia SPA.

Solución: Implementar Axios Interceptors (como se muestra en el bloque de código de arriba). El interceptor evalúa dinámicamente el localStorage justo antes de disparar el HTTPRequest.

💡 Migración de Ecosistema Recomendada

El stack tecnológico se basa en Vue 2.6.14, el cual finalizó su soporte LFE el 31 de Diciembre de 2023. Además, depende fuertemente de Vuetify 2.

  • Dependencias Aislables: Antes de actualizar Vue, es recomendable migrar los mixins (Vue 2 Options API specific) a clases puras JS como lo propuesto. De esta forma, desacoplas la lógica de negocio del framework.
  • Migración a Vite: El proyecto usa Vue CLI Webpack. Se recomienda rotar los scripts a Vite para mejorar increíblemente la rapidez de compilación.
