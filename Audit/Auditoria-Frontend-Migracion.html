1. Inventario de Obsolescencia y Deuda Técnica

🚨 Riesgo Crítico: Fin de Ciclo de Vida (EOL)
Vue 2.x alcanzó su End of Life (EOL) oficial el 31 de diciembre de 2023. Ya no recibe actualizaciones de seguridad ni de compatibilidad, lo que representa un riesgo alto para sistemas hospitalarios / financieros.
Tecnología / Patrón Estado Actual Nivel de Riesgo Observación Arquitectónica
Vue 2.6.14 Obsoleto (EOL) Crítico Sin parches de seguridad. Patrón Options API fomenta componentes monolíticos.
Vue CLI (Webpack) Mantenimiento Medio Tiempos de compilación lentos (HMR). La comunidad se movió por completo a Vite.
Vuetify 2.x Sin nuevas features Alto Incompatible con Vue 3. La actualización a Vuetify 3 tiene breaking changes masivos.
Global Mixins Antipatrón Crítico Lógica de HTTP inyectada vía mixins (ej. loginMixin.js). Causa colisión de nombres, falta de tipado y dificulta el testing.
vue2-editor / v-mask Abandonados Medio Librerías de nicho sin soporte oficial en Vue 3 o con wrappers no oficiales. Requerirá sustitución.

2. Análisis de Viabilidad y Riesgos de Migración

Viabilidad Técnica

La migración es completamente viable pero altamente compleja debido al fuerte acoplamiento con Vuetify 2 y el uso extensivo de Mixins para fetching de datos.


  • Vue 3 (Composition API): Mejora drástica del rendimiento, reutilización y tipado (TypeScript base).
  • Vite: Tiempos de arranque en frío (`npm run dev`) que pasan de decenas de segundos a ~500 milisegundos.
  • Eliminación de Mixins: Usando Composables (Hooks personalizados), funciones como llamadas a la API (Axios) se independizan totalmente de los componentes de UI.

Principales Cuellos de Botella (Riesgos)

  • El Gran Salto de Vuetify (2 → 3): Vuetify 3 fue reescrito desde cero. Muchos utilitarios y propiedades de grids cambiaron. Tablas de datos (DataTables) y modales pueden romperse inicialmente.
  • Vue Router & Vuex: La sintaxis cambia (Vuex 4 / Vue Router 4). Vuex está en deprecación a favor de Pinia.
  • Pausa de Features: Una refactorización monolítica o estilo "Big Bang" bloquearía nuevas funcionalidades por meses.

3. Estrategia de Refactorización por Fases (Sin romper Producción)

Se recomienda la estrategia de Strangler Fig Pattern (Migración Progresiva) en lugar de una reescritura desde cero.

Fase 1: Desacoplamiento Lógico (Inmediato - Aún en Vue 2)

Extraer toda la lógica de negocio (llamadas de API Axios, cálculos, formatos) fuera de los Vue Mixins hacia funciones puros de JavaScript. Actualizar a Vue 2.7 (Que trae la Composition API de forma nativa a Vue 2).

// Antes: mixins/services/loginMixin.js (Antipatrón) export default { methods: { getLogin() { return axios.post(...) } } } // Después: api/authService.js (Desacoplado) import axios from '@/plugins/axios'; export const authService = { login: (data) => axios.post('/api/users/session', data) }

Fase 2: Migración del Bundler (Webpack a Vite)

Remover @vue/cli-service y configurar Vite manteniendo Vue 2.7. Esto otorgará mejoras de DX (Developer Experience) inmediatas sin cambiar componentes visuales y modernizará el sistema de build.

Fase 3: Salto Híbrido al Ecosistema (Vue 3 + Vuetify 3)

Crear una rama paralela (feat/vue3-migration). Subir las dependencias principales a vue@3, vue-router@4 y vuetify@3. Corregir errores de consola sistemáticamente y cambiar al script setup progresivamente en componentes maestros.

<!-- Patrón Moderno Propuesto (Vue 3 + <script setup>) --> <script setup> import { ref, onMounted } from 'vue'; import { authService } from '@/api/authService'; import { useToast } from 'toast-library'; const patientData = ref([]); const isLoading = ref(false); const toast = useToast(); onMounted(async () => { isLoading.value = true; try { patientData.value = await authService.getPatient(id); } catch (err) { toast.error('Error al cargar datos'); } finally { isLoading.value = false; } }); </script>

Fase 4: Modernización del Estado Global (Vuex a Pinia)

Sustituir gradualmente los módulos de configuración y estado desde Vuex 3/4 hacia Pinia, la cual es más ligera, no usa mutaciones y tiene inferencia de tipos perfecta si a futuro se desea agregar TypeScript.

4. Soluciones Modernas y Alternativas

Si la fricción para migrar Vuetify 3 es demasiado alta debido a los breaking changes, el momento es ideal para explorar alternativas UI modernas más mantenibles y menos pesadas:

Categoría Mantenido Actual Alternativa Propuesta / Standard Moderno
UI Framework Visual Vuetify 2.x PrimeVue: Extremadamente ágil, compatible con Tailwind, componentes empresariales maduros (Datatables de alto rendimiento, modales, calendarios).

Quasar Framework: Opción Enterprise, todo en uno. Excelente para apps de administración médicas y financieras.
Estilos CSS y Utilidades SCSS / Custom CSS Tailwind CSS (v3/v4): Utilidades atómicas. Evita el CSS desordenado y previene romper la UI al borrar clases. Permite personalización total a nivel de componente.
Gestor de Estado (Store) Vuex Pinia: Es el estándar oficial actual. Módulos más limpios, sin getters engorrosos ni `commit`/`dispatch` obligatorios.
Lógica transversal Mixins Puros VueUse (`@vueuse/core`): Librería gigantesca de Composables ultra probados (sensores de ventana, scroll, debounce, localstorage).
